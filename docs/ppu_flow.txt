Design as per 20/7/26:
---------------------

The "while" loop runs based on two variables, i.e. g->is_running and "runned".

g -> is_running : it's the state of the SDL window.
runned : it's the state of the SDL window of whether it has been run or not. (initialised to false)

	while(runned == false || g->is_running){

So it will just start this while loop. After that it checks for game_events but rn g is NULL.
Then it executes the instructions , in my design I have added the fetch phase inside of the
execute() function only.

An instruction is executed and after that I check the LCDC.7 register to see if I have been
asked to switch on the LCD, if that is the case then I make a new window and set runned to
true because now I hand the control to the SDL window , so now g-> is_running is the boss
and it controls the while loop. In this "if" block I also check if runned is true or not so
that I don't make multiple instances of the SDL window on the same buffer.

Then I check if "g" isn't NULL and if it's not NULL then I start drawing and rendering it.

Now in the draw() function it first calls the "set_background()" function.

set_background():
----------------

Now first off this function calls "select_background()", this function is basically the
checking of LCDC.3 register. It sets the bacground address to 0x9800 or 0x9c00 depending
on LCDC.3 register. It also returns the end address of the tile map.
Now I loop over that tile map and over there I choose the addressing mode (via the
select_addressing_mode() function) and according to that I calculate the _tile's starting
address_.
I increment the background_mem address , which holds the tile index. Now I read 16 bytes starting
from the "start_address" and store it in a buffer and I pass that buffer into my "make_tile()"
function which makes the static data into a tile.
The first index is of the tile at the top left (refer to docs/ppu.txt for more info) , so
after creating that tile I set the "background" using this tile.

		// Set the background as the tile
